# Поправки и отрицания

Обсуждено 2026-10-26, не реализовано. Начинать, когда будут готовы новые часы движка
(таймер; реализация тишины из `feat/silence` в `main` не войдёт).

## Проблема

Что даёт `main` сейчас:

| Фраза | Выдано | Нужно |
|---|---|---|
| включи свет в ванной, ой, в спальне | ванной, спальне | спальне |
| не включи свет в ванной | ванной | ничего |
| включи свет в ванной, не в спальне | ванной, спальне | ванной |
| открой шторы, ой нет, закрой дверь, разогрей чайник | шторы, утро, чайник | дверь, чайник |

## Решения

### Два механизма

- **Поправка** («ой», «а нет», «отмена») стоит после команды и снимает её.
- **Отрицание** («не») стоит перед командой и подавляет её.

Один общий список для обоих не годится. «Не» после срабатывания сняло бы правильную
команду: «включи свет в ванной, не в спальне» дало бы спальню.

### Формат

```json
{
  "max_gap": 3.0,
  "hold": 1.0,
  "corrections": [["ой"], ["а", "нет"], ["отмена"]],
  "negations": [["не"]],
  "negation_breaks": [["а"], ["но"]],
  "scenarios": [{"name": "взлом", "order": "any", "hold": 0.0, "...": "..."}]
}
```

- Маркер — это фраза, а не слово: «а нет» состоит из двух токенов. Токены фразы
  должны идти в потоке подряд. Поэтому маркеры ищутся не бором (бор пропускает
  посторонние токены), а сравнением последних 1–3 токенов со списком фраз.
- Токены маркеров обязаны быть в словаре.
- `hold` — задержка выдачи. Её задаёт корень, сценарий может её переопределить.
  При `0` сценарий выдаётся сразу, и поправка его не снимает. Это нужно сигнализации
  и датчикам.

### Отложенная выдача

Завершённое совпадение не выдаётся сразу, а ждёт.

- Срок выдачи — время последнего шага плюс `hold`.
- Срок продлевает **шаг родственника**: новый шаг любого совпадения с тем же первым
  шагом (то есть начавшегося с того же токена потока). Посторонняя речь и датчики
  срок не продлевают. Ждать «тишины вообще» нельзя: в шумной комнате команды не
  выдавались бы никогда.
- Когда срок прошёл, срабатывание выдают часы.
- Повтор и cooldown проверяются при завершении, как сейчас. Ждущее срабатывание
  занимает токены и cooldown. Снятое освобождает их, как будто его не было.
- Схема общая для бора и для шаблонов `any`: ждут все совпадения из `completed`.

### Поправка

Поправка внутри срока:

1. Снимает **все** ждущие срабатывания.
2. Снимает частичные совпадения, в которые входит последний токен снятого. Без этого
   «открой шторы, ой нет, …, разогрей чайник» даст «утро».
3. Копиям префикса снятого («включи свет в», «включи свет») переносит начало отсчёта
   задержки на время поправки. Чужие совпадения в тех же вершинах не трогает. Для этого
   у `Partial` нужно своё время отсчёта, а не время последнего шага.

После поправки выдаётся только то, что завершилось позже неё. Посторонние слова
(«только» и т.п.) пропускаются, как обычно.

`hold = 1.0`, между токенами 0.4 с:

```
время  токен    ждут (срок)                     выдано
1.2    ванной   ванной (2.2)
1.6    и        ванной (2.2)
2.0    спальне  ванной (3.0), спальне (3.0)     ← «спальне» — шаг родственника
2.4    ой       — оба сняты
2.8    только
3.2    в
3.6    спальне  спальне (4.6)
4.6    (часы)                                   свет в спальне
```

Если фраза кончилась на «ой», ничего не выдаётся.

### Отрицание

- Отрицание открывается фразой из `negations`.
- Первое завершённое совпадение, в котором есть шаг после «не», подавляется, и
  отрицание закрывается. Подавление действует как снятие поправкой: пункты 2 и 3.
- Отрицание закрывают также фраза из `negation_breaks` и срок: `max_gap` корня, считая
  от «не» и затем от каждого нового шага любого совпадения.

```
не включи свет в ванной                → ничего
включи свет в ванной, не в спальне     → ванной
включи свет не в ванной, а в спальне   → спальне
не включи свет в ванной и в спальне    → спальне (намеренно: отрицание закрылось на «ванной»)
```

### Маркер внутри шаблона

Если токен маркера стал шагом завершённого совпадения, для этого совпадения он обычный
шаг, а его действие как маркера отменяется. Например, при шаблоне «не беспокоить»:

```
не беспокоить            → сценарий «не беспокоить»
не включи свет в ванной  → отрицание («не» стало шагом, но «не беспокоить» не завершилось)
```

Пока токен маркера стоит шагом в живом частичном совпадении, действие маркера ждёт. Ждут
и срабатывания, на которые оно повлияет. Если совпадение с маркером завершилось, маркер
отменяется; если все такие совпадения умерли, маркер применяется. Обычный маркер, которого
нет в шаблонах, применяется сразу.

### Отвергнуто

| Вариант | Почему нет |
|---|---|
| Отменять уже выданное срабатывание | команда уже выполнена; «вызвать полицию» не откатить |
| Выдавать по общей паузе («нет токенов») | в шумной комнате команды не выдаются |
| Один пул для «ой» и «не» | «не» стоит перед командой |
| Продлевать таймер всем вышестоящим вершинам | ломает `max_gap` чужих совпадений |
| «Побеждает последнее» без маркеров | «в ванной и в спальне» теряет ванную |
| Маркеры в шаблонах каждого сценария | правила разрастаются в разы |

## Шаги плана

Каждый шаг делается в своей ветке и получает свой пример потока. Старые примеры должны
запускаться. Проверка — перебором, скрипт вне репозитория.

0. [ ] Новые часы движка. Делаются отдельно, без них дальше не идти.
1. [ ] Формат: `hold` в корне и в сценарии; `corrections`, `negations`,
   `negation_breaks`; проверка правил. Обновить `smart_home.json`: у «взлома» и
   «кто-то вошёл» `hold: 0`.
2. [ ] Отложенная выдача: ждущие срабатывания, срок, продление шагом родственника,
   выдача по часам. Учесть их в `active_count` и в обрезке `_taken`. Пример
   `examples/hold.txt`.
3. [ ] Поправки: поиск фраз, снятие всех ждущих, чистка совпадений, перенос отсчёта у
   копий префикса, освобождение токенов и cooldown. Пример `examples/corrections.txt`.
4. [ ] Отрицания: открытие, подавление, закрытие разрывом и сроком. Пример
   `examples/negations.txt`.
5. [ ] Маркер внутри шаблона: отложенное применение. Сценарий «не беспокоить» в
   `smart_home.json`, поток в `examples/negations.txt`.
6. [ ] README и PLAN.md: убрать «Самоисправление» из «Вне плана».

## Открытые вопросы

Решить опросом перед соответствующим шагом.

- `hold`, `corrections`, `negations`, `negation_breaks`: обязательны ли они в корне,
  как `max_gap`, и какие значения ставить в примерах.
- Токен сразу в двух списках маркеров. Например, «а» — разрыв отрицания и начало
  «а нет»: допустимо ли это и как оно действует.
- Граница срока: выдавать, когда прошло ровно `hold`, или только когда строго больше.
