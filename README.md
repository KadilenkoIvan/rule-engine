# rule-engine

Движок правил для умного дома. На вход подаётся поток токенов (слов команд и
звуковых сигналов) с уверенностью детектора и временем, на выходе получаются
сработавшие сценарии.

## Как работает

1. В [examples/smart_home.json](examples/smart_home.json) заданы словарь токенов
   (`vocabulary`), сценарии (`scenarios`), стандартная задержка между шагами
   (`max_gap`) и стандартный порог уверенности токена (`min_score`). У сценария
   есть имя и шаблоны (`patterns`): шаблон — список шагов, шаблоны одного
   сценария — альтернативы. Сработал любой шаблон — сработал сценарий. Свои
   задержку и порог можно задать сценарию или отдельному шагу.
2. Из шаблонов строится префиксное дерево: у шаблонов с общим началом общие
   вершины. Ребро — это токен шага, его задержка и порог, поэтому шаги с одним
   токеном, но разными задержкой или порогом идут по разным рёбрам.
3. Каждый токен потока продолжает частичные совпадения по рёбрам дерева. Когда
   совпадение доходит до вершины, где заканчивается шаблон, срабатывает его
   сценарий.

Правила прохода:

- токен, для которого нет подходящего ребра, пропускается, и совпадение ждёт
  дальше;
- токен проходит по ребру, только если его уверенность не ниже порога ребра;
  иначе для этого ребра токена нет, и совпадение ждёт дальше;
- совпадение продолжается по ребру, только если от его последнего шага прошло
  не больше задержки ребра; посторонние токены этот срок не продлевают;
- когда сроки всех рёбер из вершины истекли, совпадение снимается;
- новое совпадение начинается с первого шага шаблона, если уверенность токена
  не ниже порога этого шага; задержку новое совпадение не проверяет;
- совпадение, прошедшее по ребру, остаётся и в старой вершине: копия ждёт
  другого продолжения, поэтому лишний токен со своим ребром не уводит
  совпадение в чужую ветку;
- в одной вершине может стоять только одно совпадение; из двух остаётся то,
  что началось позже, а при равном начале — то, у которого последний шаг позже;
- если из вершины, где сработал сценарий, есть продолжение, совпадение идёт
  дальше;
- сценарий не срабатывает второй раз на тех же токенах: срабатывание, у
  которого есть общий токен с уже выданным срабатыванием этого сценария, не
  выдаётся; токены сравниваются по номеру в потоке;
- после срабатывания сценарий молчит `cooldown` секунд; заглушённое
  срабатывание не занимает токены и не продлевает cooldown;
- токен, которого нет в словаре, вызывает ошибку;
- токен со временем раньше предыдущего вызывает ошибку.

## Граф

```
  ┌─включи───>( )─свет─>( )─в─>( )─┬─ванной──>( ) «свет в ванной: включить»
  │                                └─спальне─>( ) «свет в спальне: включить»
  ├─выключи──>( )─свет─>( ) «свет: выключить»
  │                      └─закрой─>( )─дверь─>( ) «ухожу из дома»
  ├─разогрей─>( )─┬─чайник─>( ) «чайник: разогреть»
  │               └─ванну──>( ) «ванна: разогреть»
●─┼─открой───>( )─шторы─>( ) «шторы: открыть»
  │                       └─разогрей─>( )─чайник─>( ) «утро»
  ├─закрой───>( )─дверь─>( ) «дверь: закрыть»
  ├─<дверь> [≥ 0.3]─>( )─<громкий звук> [10 с, ≥ 0.3]─>( ) «взлом»
  ├─<громкое открывание двери> [≥ 0.3]─>( ) «взлом»
  ├─<стекло разбилось> [≥ 0.3]─────────>( ) «взлом»
  └─<дверь>─────────>( )─<шаги> [5 с, ≥ 0.3]─>( ) «кто-то вошёл»
```

У «взлома» три шаблона, поэтому он заканчивается в трёх вершинах.

В квадратных скобках — задержка и порог ребра, если они отличаются от
стандартных (3 с и 0.5): у «взлома» задержка 10 с и порог 0.3, у шага `<шаги>`
— 5 с и 0.3. У рёбер из начала задержки нет: новое совпадение её не проверяет.

Сценарии делят ребро, только если у шага совпадают токен, задержка и порог.
Поэтому у `<дверь>` два ребра из начала: «взлом» принимает её с уверенностью от
0.3, а «кто-то вошёл» — от 0.5. Если бы ребро было общим, одному совпадению в
общей вершине пришлось бы ждать по срокам и порогам разных сценариев.

```
●        начало
( )      вершина
(*)      здесь стоит частичное совпадение
─x─>     ребро с токеном x
═x═>     ребро, по которому совпадение уже прошло
[N с]    задержка ребра, если она не стандартная
[≥ s]    порог уверенности ребра, если он не стандартный
«…»      здесь заканчивается сценарий
✓ «…»    сценарий сработал
```

## Примеры

`#N` — номер события в потоке, `@t` — его время в секундах (в выводе `run`).
«Ждёт до t» — до какого момента совпадение может продолжиться. В строке
показана ветка, к которой относится токен. В примерах с порогами после токена
указана его уверенность.

**«разогрей ванну»: выбор ветки в общей вершине**

```
#0 разогрей  ●═разогрей═>(*)─┬─чайник─>( )
                             └─ванну──>( )
#1 ванну     ●═разогрей═>(*)─┬─чайник─>( )
                             └═ванну══>( )  ✓ «ванна: разогреть»
```

Копия в вершине «разогрей» ждёт дальше: если «чайник» придёт не позже 3 с после
«разогрей», сработает ещё и «чайник: разогреть».

**«включи пожалуйста свет в ванной»: посторонний токен пропускается**

```
#0 включи      ●═включи═>(*)─свет─>( )─в─>( )─ванной─>( )
#1 пожалуйста  ●═включи═>(*)─свет─>( )─в─>( )─ванной─>( )   ребра «пожалуйста» нет: ждём
#2 свет        ●═включи═>(*)═свет═>(*)─в─>( )─ванной─>( )
#3 в           ●═включи═>(*)═свет═>(*)═в═>(*)─ванной─>( )
#4 ванной      ●═включи═>(*)═свет═>(*)═в═>(*)═ванной═>( )   ✓ «свет в ванной: включить»
```

**«открой шторы и разогрей чайник»: два совпадения сразу, короткий сценарий внутри длинного**

```
#0 открой    ●═открой═>(*)─шторы─>( )─разогрей─>( )─чайник─>( )
#1 шторы     ●═открой═>(*)═шторы═>(*)─разогрей─>( )─чайник─>( )   ✓ «шторы: открыть»
#2 и         ●═открой═>(*)═шторы═>(*)─разогрей─>( )─чайник─>( )   ребра «и» нет: ждём
#3 разогрей  ●═открой═>(*)═шторы═>(*)═разогрей═>(*)─чайник─>( )
             ●═разогрей═>(*)─чайник─>( )                          + новое из начала
#4 чайник    ●═открой═>(*)═шторы═>(*)═разогрей═>(*)═чайник═>( )   ✓ «утро»
             ●═разогрей═>(*)═чайник═>( )                          ✓ «чайник: разогреть»
```

**«разогрей разогрей чайник»: два совпадения в одной вершине склеиваются**

```
#0 разогрей  ●═разогрей═>(*)─чайник─>( )   совпадение с #0
#1 разогрей  ●═разогрей═>(*)─чайник─>( )   сюда же пришло новое с #1, место одно: остаётся #1
#2 чайник    ●═разогрей═>(*)═чайник═>( )   ✓ «чайник: разогреть» из #1 #2, один раз
```

**«выключи свет свет»: на тех же токенах сценарий второй раз не срабатывает**

```
#0 выключи  ●═выключи═>(*)─свет─>( )─закрой─>( )─дверь─>( )
#1 свет     ●═выключи═>(*)═свет═>(*)─закрой─>( )─дверь─>( )   ✓ «свет: выключить» из #0 #1
#2 свет     ●═выключи═>(*)═свет═>(*)─закрой─>( )─дверь─>( )   из #0 #2: токен #0 уже занят
```

В вершине «свет» остаётся совпадение #0 #2: начало у него то же, а последний
шаг позже. Этот пример и «включи чайник и свет в спальне», где срабатывают оба
сценария, лежат в [examples/repeats.txt](examples/repeats.txt).

**«выключи свет», пауза 5 с, «закрой дверь»: от «свет» до «закрой» больше 3 с**

```
#0 выключи  @0.0  ●═выключи═>(*)─свет─>( )─закрой─>( )─дверь─>( )
#1 свет     @0.4  ●═выключи═>(*)═свет═>(*)─закрой─>( )─дверь─>( )   ✓ «свет: выключить»
#2 закрой   @5.4  ●─выключи─>( )─свет─>( )─закрой─>( )─дверь─>( )   истекли сроки 3.0 и 3.4: совпадения сняты
                  ●═закрой═>(*)─дверь─>( )                          + новое из начала
#3 дверь    @5.8  ●═закрой═>(*)═дверь═>( )                          ✓ «дверь: закрыть»
```

В последней фразе [examples/stream.txt](examples/stream.txt) от «свет» до
«закрой» ровно 3 с, поэтому там срабатывает ещё и «ухожу из дома». «Потом»
между ними срок не продлевает.

**«выключи», `<дверь>`, «свет», `<громкий звук>`: задержка считается между шагами своего сценария**

| Событие | Что происходит |
|---|---|
| #0 выключи @0.0 | совпадение «выключи» ждёт «свет» до 3.0 |
| #1 `<дверь>` @0.5 | начинаются два совпадения: «взлом» ждёт `<громкий звук>` до 10.5, «кто-то вошёл» ждёт `<шаги>` до 5.5 |
| #2 свет @4.0 | 4.0 > 3.0: совпадение «выключи» снято, «свет: выключить» не срабатывает |
| #3 `<громкий звук>` @7.0 | 7.0 ≤ 10.5: ✓ «взлом». Срок «кто-то вошёл» истёк в 5.5, совпадение снято |

Между `<дверь>` и «свет» пауза 3.5 с, но «взлому» она не мешает: срок
отсчитывается от его собственного шага `<дверь>`, а задержка у него 10 с.

**«выключи, пожалуйста, пожалуйста, свет»: посторонние токены срок не продлевают**

```
#0 выключи     @0.0  ●═выключи═>(*)─свет─>( )   ждёт до 3.0
#1 пожалуйста  @2.5  ●═выключи═>(*)─свет─>( )   ребра «пожалуйста» нет: ждёт до 3.0
#2 пожалуйста  @5.0  ●─выключи─>( )─свет─>( )   5.0 > 3.0: совпадение снято
#3 свет        @7.5  ●─выключи─>( )─свет─>( )   «свет: выключить» не срабатывает
```

Между соседними токенами по 2.5 с, но срок отсчитывается от последнего шага
совпадения — от «выключи».

**`<дверь>`, через 4 с `<шаги>`: у шага своя задержка**

| Событие | Что происходит |
|---|---|
| #0 `<дверь>` @0.0 | «кто-то вошёл» ждёт `<шаги>` до 5.0, «взлом» ждёт `<громкий звук>` до 10.0 |
| #1 `<шаги>` @4.0 | 4.0 ≤ 5.0: ✓ «кто-то вошёл» |

Со стандартной задержкой 3 с «кто-то вошёл» здесь не сработал бы. Три последних
примера лежат в [examples/gaps.txt](examples/gaps.txt), там группы сдвинуты по
времени.

**«<дверь> <громкий звук>»: сигналы — такие же токены, у сценария несколько шаблонов**

```
#0 <дверь>         ●═<дверь> [≥ 0.3]═>(*)─<громкий звук> [10 с, ≥ 0.3]─>( )
#1 <громкий звук>  ●═<дверь> [≥ 0.3]═>(*)═<громкий звук> [10 с, ≥ 0.3]═>( )   ✓ «взлом»
```

Показана только ветка «взлома»: `<дверь>` начинает совпадение и во второй
вершине `<дверь>`, у «кто-то вошёл». Два других шаблона «взлома» — одиночные
сигналы: `<громкое открывание двери>` или `<стекло разбилось>` сразу дают
«взлом».

**«<дверь> <шаги> <громкий звук>»: лишний сигнал не мешает**

| Событие | Что происходит |
|---|---|
| #0 `<дверь>` | начинаются «взлом» и «кто-то вошёл», у каждого своя вершина `<дверь>` |
| #1 `<шаги>` | ✓ «кто-то вошёл»; «взлому» `<шаги>` не нужны, его совпадение ждёт дальше |
| #2 `<громкий звук>` | ✓ «взлом» |

Когда вершина у сценариев общая, тот же результат даёт копия: так
«включи чайник и свет в спальне» из [examples/repeats.txt](examples/repeats.txt)
даёт оба сценария.

**«<стекло разбилось>» трижды подряд: у «взлома» cooldown 60 с, тревога одна**

```
#0 <стекло разбилось>  @0.0  ●═<стекло разбилось> [≥ 0.3]═>( )   ✓ «взлом»
#1 <стекло разбилось>  @0.8  ●═<стекло разбилось> [≥ 0.3]═>( )   0.8 с после тревоги < 60 с: молчим
#2 <стекло разбилось>  @1.5  ●═<стекло разбилось> [≥ 0.3]═>( )   1.5 с < 60 с: молчим
```

Все группы сигналов лежат в [examples/alarm.txt](examples/alarm.txt).

**«выключи свет свет», первый «свет» неуверенный: токен ниже порога для ребра не существует**

| Событие | Что происходит |
|---|---|
| #0 выключи 0.95 @0.0 | совпадение «выключи» ждёт «свет» до 3.0 |
| #1 свет 0.40 @0.4 | 0.40 < 0.5: для ребра «свет» токена нет, совпадение ждёт дальше |
| #2 свет 0.90 @0.9 | ✓ «свет: выключить» из #0 #2 |

Если неуверенным будет «выключи», совпадение не начнётся вовсе, и «свет» после
него ничего не даст.

**`<дверь>`, `<громкий звук>` 0.35: у «взлома» свой порог 0.3**

| Событие | Что происходит |
|---|---|
| #0 `<дверь>` 0.90 @0.0 | «взлом» ждёт `<громкий звук>` до 10.0 |
| #1 `<громкий звук>` 0.35 @1.0 | 0.35 ≥ 0.3: ✓ «взлом» |

Со стандартным порогом 0.5 звук бы не засчитался. Так же засчитываются тихие
`<шаги>` 0.40 в «кто-то вошёл»: у этого шага свой порог 0.3.

**`<дверь>` 0.40, `<шаги>`, `<громкий звук>`: у одного токена два ребра с разными порогами**

| Событие | Что происходит |
|---|---|
| #0 `<дверь>` 0.40 @0.0 | 0.40 ≥ 0.3: «взлом» ждёт `<громкий звук>` до 10.0. 0.40 < 0.5: «кто-то вошёл» не начинается |
| #1 `<шаги>` 0.80 @1.0 | ждущего `<шаги>` совпадения нет, «кто-то вошёл» не срабатывает |
| #2 `<громкий звук>` 0.60 @2.0 | ✓ «взлом» |

Все примеры с порогами лежат в [examples/scores.txt](examples/scores.txt).

## Форматы

Правила лежат в [examples/smart_home.json](examples/smart_home.json):

```json
{
  "max_gap": 3.0,
  "min_score": 0.5,
  "vocabulary": ["разогрей", "чайник", "<дверь>", "<шаги>", "<громкий звук>",
                 "<стекло разбилось>"],
  "scenarios": [
    {"name": "чайник: разогреть", "patterns": [["разогрей", "чайник"]]},
    {"name": "взлом", "max_gap": 10.0, "min_score": 0.3, "cooldown": 60.0,
     "patterns": [["<дверь>", "<громкий звук>"], ["<стекло разбилось>"]]},
    {"name": "кто-то вошёл",
     "patterns": [["<дверь>", {"token": "<шаги>", "max_gap": 5.0, "min_score": 0.3}]]}
  ]
}
```

`max_gap` в корне обязателен: это стандартная задержка между шагами в секундах.
`min_score` в корне тоже обязателен: это стандартный порог уверенности токена,
число от 0 до 1. `patterns` — непустой список шаблонов-альтернатив, шаблон —
непустой список шагов. Шаблон записывается списком, а не строкой через пробел,
потому что в токене бывают пробелы.

Шаг — строка с токеном из словаря или объект
`{"token": ..., "max_gap": ..., "min_score": ...}`. Задержка шага — наибольшее
время от предыдущего шага шаблона до этого, порог шага — наименьшая уверенность
токена, которую шаг принимает. Обе настройки берутся у самого шага; если их там
нет — у сценария (`max_gap` и `min_score` сценария); если нет и там — из корня.
У первого шага задержки нет: новое совпадение её не проверяет, поэтому `max_gap`
у него вызывает ошибку. Порог у первого шага есть. Задержка — положительное
конечное число, порог — число от 0 до 1.

Одинаковые шаблоны в одном сценарии (те же токены с теми же задержками и
порогами) и одна последовательность шагов у двух сценариев вызывают ошибку.
Неизвестный ключ в корне, у сценария или у шага тоже вызывает ошибку: опечатка
не теряется молча.

`cooldown` — необязательный ключ сценария: неотрицательное число секунд, по
умолчанию 0. Ставит его автор правил тем сценариям, чей повтор нужно глушить;
токены движок при этом обрабатывает одинаково. В примере cooldown есть только у
«взлома»: у команды он заглушил бы настоящий повтор.

Звуковые сигналы записываются в угловых скобках: `<дверь>`, `<громкий звук>`.
Это только соглашение об именах: движок скобки не разбирает и сравнивает токены
как строки целиком. Поэтому сказанное «дверь» и звук `<дверь>` — разные токены,
и громко сказанное «закрой дверь» не станет взломом.

Потоки лежат в [examples/](examples/) (`stream.txt`, `pause.txt`, `alarm.txt`,
`repeats.txt`, `gaps.txt`, `scores.txt`): одна строка на событие, в формате
`токен уверенность время`. Токеном считается всё до двух последних чисел,
поэтому в нём бывают пробелы: `<громкий звук> 0.62 12.4`. Пустые строки и
строки, начинающиеся с `#`, пропускаются. Уверенность — число от 0 до 1, движок
сравнивает её с порогом шага.

Время задаётся в секундах: это момент, когда токен сказан. Метку ставит
детектор, а не движок, потому что порция токенов приходит к движку разом.
Начало отсчёта одно на весь поток: в работе это Unix time, в примерах — начало
записи. Задержкам нужны только разности времён.

## Файлы

- [rules.py](src/rule_engine/rules.py): словарь и сценарии, загрузка JSON, проверки;
- [graph.py](src/rule_engine/graph.py): построение и печать графа;
- [engine.py](src/rule_engine/engine.py): проход потока по графу;
- [cli.py](src/rule_engine/cli.py): командная строка.

## Запуск

```bash
uv sync
uv run rule-engine graph examples/smart_home.json                     # показать граф
uv run rule-engine run examples/smart_home.json examples/stream.txt   # прогнать поток
uv run rule-engine run examples/smart_home.json examples/pause.txt    # задержка больше 3 с
uv run rule-engine run examples/smart_home.json examples/alarm.txt    # звуковые сигналы
uv run rule-engine run examples/smart_home.json examples/repeats.txt  # копии и повторы
uv run rule-engine run examples/smart_home.json examples/gaps.txt     # задержки между шагами
uv run rule-engine run examples/smart_home.json examples/scores.txt   # пороги уверенности
uv run pytest
```
