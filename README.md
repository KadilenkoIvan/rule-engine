# rule-engine

Движок правил поверх готовых токенов. Детектор (распознавание речи, датчики) уже
превратил сигнал в поток токенов с уверенностью. Движок находит в этом потоке
заданные комбинации — сценарии умного дома.

## 1. Общая картина

Движок похож на человека, который выучил несколько фраз и слушает речь слово за
словом. После каждого слова он проверяет, не договорили ли одну из выученных
фраз до конца.

У движка два входа:

1. **Правила.** Какие слова вообще бывают (словарь) и какие фразы нужно
   узнавать (сценарии). Читаются из JSON-файла один раз при запуске.
2. **Поток событий.** Слова приходят по одному, у каждого есть уверенность
   детектора.

На выходе получаются **срабатывания**: «сценарий X собран вот из этих событий
потока».

```
examples/smart_home.json ──load_rules──► RuleSet ──build_graph──► граф (дерево вершин)
                                                                       │
examples/stream.txt ──parse_stream──► Event, Event, … ──Engine.push────┴──► Match, Match, …
```

## 2. Понятия

| Понятие | Что это | Пример | Где в коде |
|---|---|---|---|
| Токен | одно слово, строка | `"разогрей"` | обычный `str` |
| Словарь | множество всех допустимых токенов | `{"разогрей", "чайник", "пожалуйста", …}` | `RuleSet.vocabulary` |
| Сценарий | имя и последовательность токенов (фраза) | «чайник: разогреть» = `("разогрей", "чайник")` | `Scenario` в [rules.py](src/rule_engine/rules.py) |
| Событие | токен и уверенность детектора от 0 до 1 | `Event("разогрей", 0.93)` | `Event` в [engine.py](src/rule_engine/engine.py) |
| Поток | события по порядку во времени | `разогрей 0.93`, `чайник 0.84`, … | файл stream.txt или любой список `Event` |
| Позиция | номер события в потоке, считается с нуля | у `разогрей` `#0`, у `чайник` `#1` | `Step.position` |
| Шаг | позиция и само событие | `Step(0, Event("разогрей", 0.93))` | `Step` в [engine.py](src/rule_engine/engine.py) |
| Частичное совпадение | сценарий начат, но не закончен | `разогрей` пришло, `чайник` ещё нет | записи в `Engine._active` |
| Срабатывание | сценарий собран целиком | `Match("чайник: разогреть", (шаг #0, шаг #1))` | `Match` в [engine.py](src/rule_engine/engine.py) |

Уверенность (`score`) хранится в каждом событии и вместе с шагами попадает в
срабатывание. На то, сработает ли сценарий, она не влияет. Движок только
проверяет, что она лежит в пределах [0, 1].

## 3. Где лежат словарь токенов и сценарии

Всё лежит в одном файле, [examples/smart_home.json](examples/smart_home.json):

```json
{
  "vocabulary": [
    "включи", "выключи", "разогрей", "открой", "закрой",
    "свет", "чайник", "ванну", "шторы", "дверь",
    "в", "ванной", "спальне",
    "пожалуйста", "и", "потом"
  ],
  "scenarios": [
    {"name": "свет в ванной: включить", "pattern": "включи свет в ванной"},
    {"name": "свет в спальне: включить", "pattern": "включи свет в спальне"},
    {"name": "свет: выключить", "pattern": "выключи свет"},
    {"name": "чайник: разогреть", "pattern": "разогрей чайник"},
    {"name": "ванна: разогреть", "pattern": "разогрей ванну"},
    {"name": "шторы: открыть", "pattern": "открой шторы"},
    {"name": "дверь: закрыть", "pattern": "закрой дверь"},
    {"name": "утро", "pattern": "открой шторы разогрей чайник"},
    {"name": "ухожу из дома", "pattern": "выключи свет закрой дверь"}
  ]
}
```

- `vocabulary` — это словарь: список всех слов, которые может прислать
  детектор. Порядок не важен. Внутри программы список превращается в множество
  (`frozenset`), поэтому проверка «есть ли слово в словаре» выполняется
  мгновенно, сколько бы слов в нём ни было.
- `scenarios` — список сценариев. У каждого два поля:
  - `name` — имя, которое печатается при срабатывании. Оно должно быть
    уникальным.
  - `pattern` — фраза, токены через пробел. `"включи свет в ванной"`
    превращается в `("включи", "свет", "в", "ванной")`, то есть в 4 токена.

Слова в словаре бывают двух видов:

- **Встречаются в сценариях** (`разогрей`, `чайник`, `шторы`, …). Они двигают
  частичные совпадения вперёд.
- **Есть в словаре, но ни в одном сценарии** (`пожалуйста`, `и`, `потом`). В
  потоке они допустимы, но ничего не двигают и просто пропускаются.

Слов, которых нет в словаре (например, `на`), быть не должно: и в сценарии, и в
потоке такое слово вызывает ошибку.

Тесты не используют этот файл, у них свои маленькие словари прямо в коде:
`RULES` в [tests/test_engine.py](tests/test_engine.py) и функция `rules()` в
[tests/test_rules.py](tests/test_rules.py). Пример из `examples/` используется
только в [tests/test_cli.py](tests/test_cli.py).

### Формат потока

[examples/stream.txt](examples/stream.txt): одна строка — одно событие,
`токен уверенность`. Пустые строки и строки, начинающиеся с `#`, пропускаются.

```
# «разогрей ванну»
разогрей 0.93
ванну 0.81
```

Кто кого использует:

- `rules.py` берёт только стандартную библиотеку Python (`json`, `dataclasses`,
  `pathlib`);
- `graph.py` использует `rules.py`;
- `engine.py` использует `graph.py` и `rules.py`;
- `cli.py` использует все три.

Каждый слой знает только то, что ниже него. `rules.py` ничего не знает о графе,
`graph.py` — о потоке, `engine.py` — о файлах и командной строке.

## 5. Последовательность действий

### Команда `uv run rule-engine run examples/smart_home.json examples/stream.txt`

1. **Запуск.** uv находит в pyproject.toml строку
   `rule-engine = "rule_engine.cli:main"` и вызывает функцию `main()` из
   cli.py.
2. **Разбор аргументов.** Модуль `argparse` получает `command = "run"`,
   `rules = Path("examples/smart_home.json")` и
   `stream = Path("examples/stream.txt")`. Если какого-то аргумента не хватает,
   argparse печатает подсказку и завершает программу.
3. **Чтение правил** (`load_rules`):
   - файл читается как текст в кодировке UTF-8, и `json.loads` превращает его в
     словарь Python `{"vocabulary": [...], "scenarios": [...]}`;
   - `RuleSet.from_dict` делит каждый `pattern` по пробелам и создаёт,
     например, `Scenario("чайник: разогреть", ("разогрей", "чайник"))`, а
     список слов превращает в `frozenset`;
   - при создании `RuleSet` автоматически вызывается `__post_init__`, который
     проверяет правила (раздел 10). Если что-то не так, возникает ошибка и
     программа останавливается.
4. **Создание движка** (`Engine(rules)`):
   - словарь сохраняется в `_vocabulary`;
   - строится граф `build_graph(rules)`, его корень сохраняется в `_root`
     (раздел 6);
   - создаётся пустой словарь частичных совпадений `_active = {}`;
   - счётчик позиций обнуляется: `_position = 0`.
5. **Чтение потока** (`parse_stream`). Это генератор: он не читает файл целиком
   в память, а отдаёт события по одному, по мере чтения строк. С каждой
   строкой он делает следующее:
   - обрезает пробелы по краям;
   - пропускает пустые строки и строки, начинающиеся с `#` (это комментарии);
   - делит строку по пробелам; частей должно быть ровно две, иначе ошибка с
     номером строки;
   - превращает `"разогрей 0.93"` в `Event("разогрей", 0.93)`; при создании
     `Event` проверяется, что 0.93 лежит в [0, 1].
6. **Обработка события.** `engine.push(event)` возвращает список срабатываний
   на этом событии, обычно пустой (раздел 7). Каждое срабатывание сразу
   печатается через `format_match`.
7. **Итог.** После последнего события печатается, сколько частичных совпадений
   осталось незаконченными (`active_count`).

### Команда `uv run rule-engine graph examples/smart_home.json`

Шаги 1–3 те же. Затем `build_graph` строит граф, `render` превращает его в
текстовую картинку, и `print` её печатает. Поток для этой команды не нужен.

### Из кода

```python
from pathlib import Path

from rule_engine import Engine, Event, load_rules

engine = Engine(load_rules(Path("examples/smart_home.json")))
engine.push(Event("разогрей", 0.93))   # []
engine.push(Event("чайник", 0.84))     # [Match(scenario='чайник: разогреть', ...)]
```

## 6. Алгоритм 1: построение графа (префиксное дерево)

### Идея

Граф устроен как дерево:

- **вершина** означает «что уже услышано с начала фразы»;
- **ребро** подписано токеном и ведёт к вершине «услышано на одно слово
  больше»;
- **корень** означает «ещё ничего не услышано».

Главное свойство такого дерева: если у двух сценариев одинаковое начало, в
дереве это начало одно, общее. Сценарии «разогрей чайник» и «разогрей ванну»
проходят через одну вершину «разогрей» и расходятся только на втором слове.
Такое дерево называют **префиксным деревом** (trie); префикс — это начало
последовательности.

На граф можно смотреть как на **конечный автомат**: вершина — это состояние,
ребро — переход по токену, а вершина с именем сценария — конечное состояние.

### Вершина (`Node`)

```python
@dataclass(eq=False)
class Node:
    children: dict[str, "Node"]   # рёбра: токен → следующая вершина
    scenario: str | None = None   # имя сценария, если он здесь заканчивается
```

- `children` — рёбра, выходящие из вершины. Например, у вершины «разогрей»
  `children = {"чайник": <вершина>, "ванну": <вершина>}`. Это словарь (`dict`),
  поэтому ребро по токену находится мгновенно, без перебора.
- `scenario` — имя сценария, который заканчивается в этой вершине, или `None`,
  если здесь ничего не заканчивается.
- `eq=False` означает, что вершины сравниваются «по личности», а не по
  содержимому. Две разные вершины без детей не считаются равными. Это нужно
  потому, что движок использует вершину как ключ словаря `_active` (раздел 7),
  и разные вершины не должны там слипаться.

### Построение (`build_graph`)

Для каждого сценария идём от корня по его токенам:

- если ребро с таким токеном уже есть, идём по нему, то есть переиспользуем
  общее начало;
- если ребра нет, создаём новую вершину и ребро к ней;
- в последней вершине записываем имя сценария. Если там уже записан другой
  сценарий, это ошибка: две одинаковые фразы.

Пример по шагам на четырёх сценариях, которые вставляются в порядке из файла:

1. **«разогрей чайник».** У корня нет ребра `разогрей`, создаём вершину Р. У Р
   нет ребра `чайник`, создаём вершину Ч. Записываем в Ч имя «чайник:
   разогреть».
2. **«разогрей ванну».** У корня **уже есть** ребро `разогрей`, идём в Р, новую
   вершину не создаём. У Р нет ребра `ванну`, создаём вершину В и записываем в
   неё «ванна: разогреть».
3. **«открой шторы».** Создаём вершины О и Ш, в Ш записываем «шторы: открыть».
4. **«открой шторы разогрей чайник».** Рёбра `открой` и `шторы` уже есть,
   доходим до Ш. У Ш нет ребра `разогрей`, создаём вершину Р2, затем под ней
   Ч2. В Ч2 записываем «утро».

```
(корень)
├─ разогрей (Р)
│  ├─ чайник (Ч)   ⇒ чайник: разогреть
│  └─ ванну (В)    ⇒ ванна: разогреть
└─ открой (О)
   └─ шторы (Ш)    ⇒ шторы: открыть
      └─ разогрей (Р2)
         └─ чайник (Ч2)  ⇒ утро
```

Обратите внимание на две вещи:

- **Р и Р2 — разные вершины**, хотя токен у них один. Р означает «с начала
  услышали *разогрей*», а Р2 — «услышали *открой шторы разогрей*». Вершину
  определяет весь путь от корня, а не последнее слово.
- **Ш одновременно конечная и промежуточная.** В ней заканчивается «шторы:
  открыть», и из неё же идёт продолжение к «утру».

Полный граф для [examples/smart_home.json](examples/smart_home.json), как его
печатает `rule-engine graph`:

```
(начало)
├─ включи
│  └─ свет
│     └─ в
│        ├─ ванной  ⇒ свет в ванной: включить
│        └─ спальне  ⇒ свет в спальне: включить
├─ выключи
│  └─ свет  ⇒ свет: выключить
│     └─ закрой
│        └─ дверь  ⇒ ухожу из дома
├─ разогрей
│  ├─ чайник  ⇒ чайник: разогреть
│  └─ ванну  ⇒ ванна: разогреть
├─ открой
│  └─ шторы  ⇒ шторы: открыть
│     └─ разогрей
│        └─ чайник  ⇒ утро
└─ закрой
   └─ дверь  ⇒ дверь: закрыть
```

В этом графе 18 вершин без корня. Суммарная длина всех сценариев — 26 токенов,
так что общие начала сэкономили 8 вершин.

### Вспомогательные функции

- `graph_size` считает вершины рекурсивно: для каждого ребёнка это 1 плюс все
  вершины под ним. Корень не считается. Для примера получается 18.
- `render` обходит дерево в глубину (сначала до конца первую ветку, потом
  следующую) и рисует каждую вершину строкой:
  - `├─` — у вершины ниже есть ещё братья;
  - `└─` — это последний брат;
  - `│` — вертикальная линия, идущая к следующим братьям родителя;
  - `⇒ имя` — здесь заканчивается сценарий.

**Стоимость построения:** каждый токен каждого сценария обрабатывается один
раз, а поиск ребра в словаре мгновенный. Время построения пропорционально
суммарной длине сценариев.

## 7. Алгоритм 2: проход потока по графу

### Что движок помнит между событиями

- **`_active`** — словарь «вершина → путь». Каждая запись — одно частичное
  совпадение: «мы стоим в этой вершине графа и дошли до неё вот этими шагами
  потока». Путь — это кортеж шагов `(Step, Step, …)`. Например:
  `{вершина «включи свет»: (шаг #0 «включи», шаг #2 «свет»)}`.
- **`_position`** — номер, который получит следующее событие.
- **Корень в `_active` не хранится.** Он активен всегда: любое событие может
  начать новый сценарий с нуля.

### Что делает `Engine.push(event)`

1. **Проверка словаря.** Если токена нет в словаре, возникает ошибка
   `ValueError: токена 'на' нет в словаре`.
2. **Номер события.** Создаётся `step = Step(_position, event)`, затем
   `_position` увеличивается на 1.
3. **Новое состояние.** Заводятся пустой словарь `active` (сюда соберутся
   частичные совпадения после этого события) и пустой список срабатываний
   `matches`.
4. **Каждое старое частичное совпадение** `(вершина, путь)` из `_active`
   обрабатывается так:
   - если из вершины есть ребро с этим токеном, совпадение **переходит** по
     ребру: `enter(ребёнок, путь + (step,))`;
   - если ребра нет, токен для этого совпадения посторонний, и совпадение
     **остаётся** в той же вершине с тем же путём: `keep(вершина, путь)`.
5. **Корень.** Если из корня есть ребро с этим токеном, начинается новое
   частичное совпадение: `enter(ребёнок_корня, (step,))`.
6. **Замена состояния.** `_active = active`, новое состояние заменяет старое, и
   функция возвращает `matches`.

Внутри `push` есть две вспомогательные функции.

`enter(вершина, путь)` — «пришли в вершину»:

- если в вершине заканчивается сценарий, в `matches` добавляется
  `Match(имя, путь)` — это и есть **срабатывание**;
- если из вершины есть продолжения, вызывается `keep(вершина, путь)`:
  совпадение живёт дальше, потому что может собраться и более длинный
  сценарий;
- если продолжений нет, совпадение не сохраняется: оно отработало и исчезает.

`keep(вершина, путь)` — «сохранить совпадение в новом состоянии»:

- если вершина в `active` ещё свободна, совпадение кладётся туда;
- если вершина уже занята другим совпадением, остаётся то, которое началось
  позже, то есть у которого номер первого шага больше.

**Почему новое состояние собирается в отдельном словаре, а не правится
старое.** Одно событие должно сдвинуть каждое совпадение максимум на один шаг.
Если бы `_active` менялся на ходу, совпадение, которое только что перешло в
новую вершину, могло бы обработать тот же токен ещё раз.

**Почему путь — кортеж.** Кортеж нельзя изменить, а `путь + (step,)` создаёт
новый кортеж. Поэтому путь, уже отданный в `Match`, никогда не испортится.
Например, на токене «шторы» в срабатывание «шторы: открыть» и в `active`
попадает один и тот же кортеж `(#0, #1)`. Когда совпадение позже дойдёт до
«утра», создастся новый кортеж `(#0, #1, #3)`, а срабатывание «шторы» по-прежнему
будет содержать `(#0, #1)`.

### Пример 1: посторонние слова пропускаются

Поток «включи пожалуйста свет в ванной»:

| # | токен | что происходит | `_active` после | срабатывания |
|---|---|---|---|---|
| 0 | включи | Старых совпадений нет. Из корня есть ребро `включи`, появляется новое совпадение в вершине «включи». | «включи»: (#0) | — |
| 1 | пожалуйста | Из «включи» нет ребра `пожалуйста`, совпадение остаётся на месте. Из корня такого ребра тоже нет. | «включи»: (#0) | — |
| 2 | свет | Из «включи» есть ребро `свет`, совпадение переходит. Из корня ребра `свет` нет: ни один сценарий не начинается со слова «свет». | «включи свет»: (#0 #2) | — |
| 3 | в | Совпадение переходит дальше. | «включи свет в»: (#0 #2 #3) | — |
| 4 | ванной | Совпадение переходит в вершину «включи свет в ванной», где заканчивается сценарий: срабатывание. Продолжений нет, совпадение исчезает. | пусто | свет в ванной: включить (#0 #2 #3 #4) |

В срабатывании нет шага #1: слово «пожалуйста» в сценарий не входит.

### Пример 2: общее начало, два совпадения одновременно, вложенные сценарии

Поток «открой шторы и разогрей чайник»:

| # | токен | что происходит | `_active` после | срабатывания |
|---|---|---|---|---|
| 0 | открой | Из корня появляется совпадение в вершине «открой». | «открой»: (#0) | — |
| 1 | шторы | Переход в «открой шторы», где заканчивается «шторы: открыть»: срабатывание. Но из вершины есть продолжение (`разогрей`, к «утру»), поэтому совпадение остаётся. | «открой шторы»: (#0 #1) | шторы: открыть (#0 #1) |
| 2 | и | Посторонний токен, совпадение стоит на месте. | «открой шторы»: (#0 #1) | — |
| 3 | разогрей | (а) Старое совпадение: из «открой шторы» есть ребро `разогрей`, оно переходит. (б) Корень: у него тоже есть ребро `разогрей`, появляется новое совпадение. | «открой шторы разогрей»: (#0 #1 #3); «разогрей»: (#3) | — |
| 4 | чайник | (а) Переход в «…разогрей чайник»: срабатывает «утро», продолжений нет, совпадение исчезает. (б) Переход в «разогрей чайник»: срабатывает «чайник: разогреть», совпадение исчезает. | пусто | утро (#0 #1 #3 #4); чайник: разогреть (#3 #4) |

Что здесь видно:

- одно событие (#3, «разогрей») участвует сразу в двух сценариях;
- короткий сценарий («шторы: открыть») сработал и не помешал длинному
  («утро»);
- на одном токене может быть несколько срабатываний. Сначала идут старые
  совпадения в том порядке, в каком они лежат в `_active`, потом новое
  совпадение из корня.

### Пример 3: два одинаковых начала склеиваются

Поток «разогрей разогрей чайник»:

| # | токен | что происходит | `_active` после | срабатывания |
|---|---|---|---|---|
| 0 | разогрей | Из корня появляется совпадение в вершине «разогрей». | «разогрей»: (#0) | — |
| 1 | разогрей | (а) Старое совпадение: из «разогрей» нет ребра `разогрей`, оно остаётся, и `keep` кладёт его в вершину «разогрей». (б) Корень: новое совпадение попадает в ту же вершину. Вершина занята, поэтому `keep` сравнивает: старое началось на #0, новое на #1, остаётся новое. | «разогрей»: (#1) | — |
| 2 | чайник | Переход в «разогрей чайник», срабатывание. | пусто | чайник: разогреть (#1 #2) |

Сценарий сработал один раз, и в нём шаги #1 и #2.

### Пример 4: закончившееся совпадение не срабатывает повторно

Поток «разогрей чайник чайник». На #1 сценарий срабатывает; у вершины нет
продолжений, и совпадение исчезает. На #2 `_active` пуст, а из корня ребра
`чайник` нет, поэтому ничего не происходит.

### Пример 5: весь поток из examples/stream.txt

```
$ uv run rule-engine run examples/smart_home.json examples/stream.txt
свет в ванной: включить  ←  включи#0 свет#2 в#3 ванной#4
ванна: разогреть  ←  разогрей#5 ванну#6
шторы: открыть  ←  открой#7 шторы#8
утро  ←  открой#7 шторы#8 разогрей#10 чайник#11
чайник: разогреть  ←  разогрей#10 чайник#11
свет: выключить  ←  выключи#12 свет#13
ухожу из дома  ←  выключи#12 свет#13 закрой#15 дверь#16
дверь: закрыть  ←  закрой#15 дверь#16
активных частичных совпадений в конце потока: 0
```

Фраза «выключи свет, потом закрой дверь» разбирается так же, как пример 2.
«свет: выключить» срабатывает и остаётся ждать продолжения. На «закрой» одно
совпадение идёт к «ухожу из дома», а из корня начинается «дверь: закрыть». На
«дверь» срабатывают оба.

## 8. Ограничение числа частичных совпадений

В `_active` ключом служит вершина, а ключи в словаре не повторяются. Поэтому в
одной вершине не больше одного совпадения, а всего их не больше, чем вершин (18
в примере). На деле ещё меньше: в `_active` попадают только вершины, у которых
есть продолжения, а в листьях совпадения сразу исчезают. В примере таких вершин
11.

**Почему склеивание не теряет срабатываний.** Оба совпадения стоят в одной
вершине, значит, ждут одних и тех же следующих токенов. Они закончились бы на
одном и том же событии и дали бы одно и то же имя сценария, то есть второе дало
бы лишь дубль. Остаётся то, что началось позже, самое свежее.

Каждый `push` перебирает только `_active` и один раз заглядывает в корень.
Поэтому работа на одно событие не растёт с длиной потока: она ограничена
размером графа.

## 9. Поток порциями

`_active` и `_position` — поля объекта `Engine`, и они сохраняются между
вызовами. Поэтому неважно, как поток нарезан на порции:

```python
engine = Engine(rules)
engine.feed([Event("включи", 0.9), Event("свет", 0.9)])   # [] — сценарий не закончен
engine.feed([Event("в", 0.9), Event("ванной", 0.9)])      # [Match('свет в ванной: включить', шаги #0 #1 #2 #3)]
```

Первая порция оставила в `_active` совпадение «включи свет»: (#0 #1), вторая
его продолжила. Позиции сквозные: события второй порции получили номера #2 и
#3, а не #0 и #1.

- `feed(events)` — это просто цикл: он вызывает `push` для каждого события и
  склеивает списки срабатываний.
- `push(event)` обрабатывает одно событие. Так работает CLI: он печатает
  срабатывание сразу, как только оно случилось.

Состояние живёт в конкретном объекте: новый `Engine` начинает с нуля.

## 10. Что считается ошибкой

| Проверка | Где | Пример | Сообщение |
|---|---|---|---|
| Слова сценария нет в словаре | `RuleSet.__post_init__` | `"pattern": "свари кофе"` | `сценарий 'кофе': токенов ['свари', 'кофе'] нет в словаре` |
| Пустой сценарий | там же | `"pattern": "  "` | `сценарий 'пусто' не содержит токенов` |
| Имя сценария повторяется | там же | два сценария с именем «чайник» | `сценарий 'чайник' объявлен дважды` |
| Две одинаковые фразы | `build_graph` | у «чайник» и «кипяток» обоих `разогрей чайник` | `сценарии 'чайник' и 'кипяток' задают одну и ту же последовательность токенов` |
| Нет поля в JSON | `RuleSet.from_dict` | нет `"vocabulary"` | `KeyError: 'vocabulary'` |
| Строка потока не из двух частей | `parse_stream` | `разогрей` или `разогрей 0.9 лишнее` | `строка 5: ожидается «токен уверенность», получено 'разогрей'` |
| Уверенность — не число | `parse_stream` (`float`) | `разогрей много` | `could not convert string to float: 'много'` |
| Уверенность вне [0, 1] | `Event.__post_init__` | `разогрей 1.5` | `уверенность 1.5 токена 'разогрей' вне [0, 1]` |
| Токена потока нет в словаре | `Engine.push` | `на 0.9` | `токена 'на' нет в словаре` |

Любая ошибка останавливает обработку. Ничего не подменяется и молча не
пропускается.

## 11. Что на выходе

В командной строке: `утро  ←  открой#0 шторы#1 разогрей#3 чайник#4`. Слева от
стрелки имя сценария, справа шаги в виде «токен#позиция».

В коде это объект `Match`:

```python
Match(scenario='чайник: разогреть',
      steps=(Step(position=0, event=Event(token='разогрей', score=0.93)),
             Step(position=1, event=Event(token='чайник', score=0.84))))
```

`Event`, `Step` и `Match` неизменяемы (`frozen=True` и `NamedTuple`):
полученное срабатывание нельзя случайно испортить.
