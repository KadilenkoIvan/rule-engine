# rule-engine

Движок правил для умного дома. На вход подаётся поток токенов (слов команд и
звуковых сигналов) с уверенностью детектора и временем, на выходе получаются
сработавшие сценарии.

## Использование

### Установка

```bash
uv sync   # движок, командная строка и веб-интерфейс (FastAPI, uvicorn, Jinja2)
```

### Выбор интерфейса

Первый аргумент выбирает интерфейс, остальные получает он сам:

```bash
uv run rule-engine cli …   # командная строка
uv run rule-engine web …   # веб-интерфейс
```

Оба работают с одним и тем же движком, поэтому на одних правилах и потоке дают
одни и те же срабатывания.

### Командная строка

```bash
uv run rule-engine cli graph examples/smart_home.json                     # граф сценариев
uv run rule-engine cli run examples/smart_home.json examples/stream.txt   # прогнать поток
```

`graph` печатает граф деревом, `run` — строку на каждое срабатывание и число
незавершённых совпадений в конце. Форматы правил, потока и вывода описаны в
разделе [Форматы](#форматы), все примеры — в разделе [Все примеры](#все-примеры).
Ошибка в правилах или потоке завершает команду исключением с текстом ошибки.

### Веб-интерфейс

```bash
uv run rule-engine web examples                            # http://127.0.0.1:8000
uv run rule-engine web examples --host 0.0.0.0 --port 9000
```

`examples` — папка с правилами `*.json` и потоками `*.txt`: они появятся в
выпадающих списках, первые по алфавиту открыты сразу. Сервер останавливается по
Ctrl+C.

Слева два поля: «Правила» и «Поток». Текст в них можно править или выбрать
пример из списка. Справа две вкладки.

- **Граф.** Перерисовывается при каждой правке правил. Если в правилах ошибка,
  вместо графа показан её текст. Под деревом — шаблоны `any` («В любом
  порядке»).
- **Прогон.** «Прогнать поток» показывает по кадру на событие. Кадры листают
  кнопки ◀ ▶, ползунок и стрелки клавиатуры. Клик по срабатыванию в колонке
  «Все срабатывания» открывает его кадр. В кадре — событие, сработавшие
  сценарии, блок «Почему не продвинулось», граф с состоянием, наборы `any` с
  закрытыми шагами и таблица частичных совпадений: где стоит, какие шаги
  собраны, уверенность, до какого момента ждёт. Если строка потока неверна,
  видны кадры до неё и текст ошибки.

После первого прогона он пересчитывается сам при любой правке или смене правил и
потока и остаётся на том же кадре. Пока ответ не пришёл, панель полупрозрачная.

Блок «Почему не продвинулось» объясняет, почему токен кадра ничего не сдвинул
или сценарий не сработал. Метка слева — причина:

| Метка | Что случилось |
|---|---|
| порог токена | уверенность токена ниже порога шага (`min_score`): ребро или шаг набора его не пустили, новое совпадение не началось |
| общая уверенность | шаблон собран, но среднее геометрическое ниже `min_confidence`; или совпадение отсеяно заранее: даже с уверенностью 1.0 у остальных шагов оно не дотянет до порога |
| задержка | токен подошёл бы, но пришёл позже срока (`max_gap` от предыдущего шага) |
| cooldown | сценарий сработал недавно и молчит |
| повтор | токены уже вошли в выданное срабатывание этого сценария |

Если токен не ждёт ни одно ребро и ни один набор, блок так и говорит: токен
пропущен. Совпадения, снятые по сроку без связи с токеном кадра, свёрнуты в
строку «Снято по сроку».

Обозначения на графе:

| Знак | Значение |
|---|---|
| ● | начало |
| синяя вершина, `×2` | здесь стоят частичные совпадения, `×2` — сколько их |
| синее ребро | пройдено совпадениями этого кадра |
| зелёная вершина, `✓ «…»` | сценарий сработал в этом кадре |
| красное пунктирное ребро, красная рамка набора | токен кадра сюда не пустили: порог или задержка |
| `● ○` в наборе `any` | закрытые и открытые шаги набора |

## Как работает

1. В [examples/smart_home.json](examples/smart_home.json) заданы словарь токенов
   (`vocabulary`), сценарии (`scenarios`), стандартная задержка между шагами
   (`max_gap`), стандартный порог уверенности токена (`min_score`) и
   стандартный порог общей уверенности (`min_confidence`). У сценария есть имя
   и шаблоны (`patterns`): шаблон — список шагов, шаблоны одного сценария —
   альтернативы. Сработал любой шаблон — сработал сценарий. Свои задержку и
   порог токена можно задать сценарию или отдельному шагу, свой порог общей
   уверенности — сценарию. По умолчанию шаги идут по порядку шаблона, а у
   сценария с `"order": "any"` — в любом порядке.
2. Из шаблонов строится префиксное дерево: у шаблонов с общим началом общие
   вершины. Ребро — это токен шага, его задержка и порог, поэтому шаги с одним
   токеном, но разными задержкой или порогом идут по разным рёбрам. Шаблоны
   `any` в дерево не входят: их совпадение — набор уже собранных шагов.
3. Каждый токен потока продолжает частичные совпадения по рёбрам дерева и
   добавляется в наборы шаблонов `any`. Когда совпадение доходит до вершины, где
   заканчивается шаблон, или набор собран целиком, срабатывает сценарий, если
   общая уверенность совпадения не ниже порога сценария.

Правила прохода:

- токен, для которого нет подходящего ребра, пропускается, и совпадение ждёт
  дальше;
- токен проходит по ребру, только если его уверенность не ниже порога ребра;
  иначе для этого ребра токена нет, и совпадение ждёт дальше;
- совпадение продолжается по ребру, только если от его последнего шага прошло
  не больше задержки ребра; посторонние токены этот срок не продлевают;
- когда сроки всех рёбер из вершины истекли, совпадение снимается;
- новое совпадение начинается с первого шага шаблона, если уверенность токена
  не ниже порога этого шага; задержку новое совпадение не проверяет;
- совпадение, прошедшее по ребру, остаётся и в старой вершине: копия ждёт
  другого продолжения, поэтому лишний токен со своим ребром не уводит
  совпадение в чужую ветку;
- общая уверенность совпадения — среднее геометрическое уверенностей его
  токенов: `(s1·…·sk)^(1/k)`; сценарий срабатывает, только если она не ниже
  его порога `min_confidence`;
- в одной вершине могут стоять несколько совпадений: совпадение вытесняет
  другое, если его последний шаг не раньше, а произведение уверенностей не
  меньше; поэтому рядом могут стоять свежее совпадение и более уверенное; если
  равны и последний шаг, и произведение, остаётся начавшееся позже;
- совпадение снимается сразу, если даже при уверенности 1.0 у всех оставшихся
  шагов оно не дотянет до порога ни одного сценария, чей шаблон кончается ниже
  (ранний отсев);
- если из вершины, где сработал сценарий, есть продолжение, совпадение идёт
  дальше;
- в шаблоне `any` токен закрывает любой ещё не закрытый шаг со своим токеном,
  если проходит его порог и укладывается в задержку от последнего шага
  совпадения; начать набор может любой шаг; одинаковые шаги ждут разных
  событий: `[<шаги>, <шаги>]` собирается из двух `<шаги>`; разные порядки
  прихода дают одно состояние — набор собранных шагов; копии, вытеснение и
  ранний отсев — как в вершине дерева;
- сценарий не срабатывает второй раз на тех же токенах: срабатывание, у
  которого есть общий токен с уже выданным срабатыванием этого сценария, не
  выдаётся; токены сравниваются по номеру в потоке;
- поэтому из совпадений одного сценария, завершившихся на одном токене,
  выдаётся одно: самое уверенное, а при равной уверенности — начавшееся позже;
- после срабатывания сценарий молчит `cooldown` секунд; заглушённое
  срабатывание не занимает токены и не продлевает cooldown;
- токен, которого нет в словаре, вызывает ошибку;
- токен со временем раньше предыдущего вызывает ошибку.

## Граф

```
  ┌─включи───>( )─свет─>( )─в─>( )─┬─ванной──>( ) «свет в ванной: включить»
  │                                └─спальне─>( ) «свет в спальне: включить»
  ├─выключи──>( )─свет─>( ) «свет: выключить»
  │                      └─закрой─>( )─дверь─>( ) «ухожу из дома»
  ├─разогрей─>( )─┬─чайник─>( ) «чайник: разогреть»
  │               └─ванну──>( ) «ванна: разогреть»
●─┼─открой───>( )─шторы─>( ) «шторы: открыть»
  │                       └─разогрей─>( )─чайник─>( ) «утро»
  ├─закрой───>( )─дверь─>( ) «дверь: закрыть»
  └─<дверь>──>( )─<шаги> [5 с, ≥ 0.3]─>( ) «кто-то вошёл»

в любом порядке, мимо дерева:
  {<дверь>, <громкий звук>} [10 с, ≥ 0.3]  «взлом»
  {<громкое открывание двери>} [≥ 0.3]      «взлом»
  {<стекло разбилось>} [≥ 0.3]              «взлом»
```

У «взлома» `"order": "any"` и три шаблона: пара сигналов в любом порядке и два
одиночных сигнала.

В квадратных скобках — задержка и порог, если они отличаются от стандартных
(3 с и 0.5): у «взлома» задержка 10 с и порог 0.3, у шага `<шаги>` — 5 с и 0.3.
У рёбер из начала задержки нет: новое совпадение её не проверяет. У набора
задержка одна на все шаги: она отсчитывается от последнего пришедшего сигнала.

Сценарии делят ребро, только если у шага совпадают токен, задержка и порог.
Иначе одному совпадению в общей вершине пришлось бы ждать по срокам и порогам
разных сценариев.

Порог общей уверенности — настройка сценария, а не ребра, поэтому на графе его
нет: у «ухожу из дома» он 0.8, у остальных сценариев стандартный, 0.6.

```
●        начало
( )      вершина
(*)      здесь стоит частичное совпадение
─x─>     ребро с токеном x
═x═>     ребро, по которому совпадение уже прошло
[N с]    задержка ребра, если она не стандартная
[≥ s]    порог уверенности ребра, если он не стандартный
{x, y}   набор шаблона any: какие шаги уже собраны или нужны
«…»      здесь заканчивается сценарий
✓ «…»    сценарий сработал
```

## Примеры

`#N` — номер события в потоке, `@t` — его время в секундах.
«Ждёт до t» — до какого момента совпадение может продолжиться. В строке
показана ветка, к которой относится токен. В примерах с порогами после токена
указана его уверенность, а после сработавшего сценария в скобках — общая
уверенность.

**«разогрей ванну»: выбор ветки в общей вершине**

```
#0 разогрей  ●═разогрей═>(*)─┬─чайник─>( )
                             └─ванну──>( )
#1 ванну     ●═разогрей═>(*)─┬─чайник─>( )
                             └═ванну══>( )  ✓ «ванна: разогреть»
```

Копия в вершине «разогрей» ждёт дальше: если «чайник» придёт не позже 3 с после
«разогрей», сработает ещё и «чайник: разогреть».

**«включи пожалуйста свет в ванной»: посторонний токен пропускается**

```
#0 включи      ●═включи═>(*)─свет─>( )─в─>( )─ванной─>( )
#1 пожалуйста  ●═включи═>(*)─свет─>( )─в─>( )─ванной─>( )   ребра «пожалуйста» нет: ждём
#2 свет        ●═включи═>(*)═свет═>(*)─в─>( )─ванной─>( )
#3 в           ●═включи═>(*)═свет═>(*)═в═>(*)─ванной─>( )
#4 ванной      ●═включи═>(*)═свет═>(*)═в═>(*)═ванной═>( )   ✓ «свет в ванной: включить»
```

**«открой шторы и разогрей чайник»: два совпадения сразу, короткий сценарий внутри длинного**

```
#0 открой    ●═открой═>(*)─шторы─>( )─разогрей─>( )─чайник─>( )
#1 шторы     ●═открой═>(*)═шторы═>(*)─разогрей─>( )─чайник─>( )   ✓ «шторы: открыть»
#2 и         ●═открой═>(*)═шторы═>(*)─разогрей─>( )─чайник─>( )   ребра «и» нет: ждём
#3 разогрей  ●═открой═>(*)═шторы═>(*)═разогрей═>(*)─чайник─>( )
             ●═разогрей═>(*)─чайник─>( )                          + новое из начала
#4 чайник    ●═открой═>(*)═шторы═>(*)═разогрей═>(*)═чайник═>( )   ✓ «утро»
             ●═разогрей═>(*)═чайник═>( )                          ✓ «чайник: разогреть»
```

**«разогрей разогрей чайник» с одинаковой уверенностью: свежее совпадение вытесняет старое**

```
#0 разогрей  ●═разогрей═>(*)─чайник─>( )   совпадение с #0
#1 разогрей  ●═разогрей═>(*)─чайник─>( )   новое с #1 свежее и не менее уверенное: #0 вытеснено
#2 чайник    ●═разогрей═>(*)═чайник═>( )   ✓ «чайник: разогреть» из #1 #2, один раз
```

Если бы первое «разогрей» было увереннее второго, в вершине стояли бы оба:
так устроен пример с двумя `<дверь>` ниже.

**«выключи свет свет»: на тех же токенах сценарий второй раз не срабатывает**

```
#0 выключи  ●═выключи═>(*)─свет─>( )─закрой─>( )─дверь─>( )
#1 свет     ●═выключи═>(*)═свет═>(*)─закрой─>( )─дверь─>( )   ✓ «свет: выключить» из #0 #1
#2 свет     ●═выключи═>(*)═свет═>(*)─закрой─>( )─дверь─>( )   из #0 #2: токен #0 уже занят
```

Совпадение #0 #2 остаётся в вершине «свет» и ждёт «закрой»: оно свежее. #0 #1
оно вытесняет, только если второй «свет» не менее уверенный, чем первый. Этот
пример и «включи чайник и свет в спальне», где срабатывают оба сценария, лежат
в [examples/repeats.txt](examples/repeats.txt).

**«выключи свет», пауза 5 с, «закрой дверь»: от «свет» до «закрой» больше 3 с**

```
#0 выключи  @0.0  ●═выключи═>(*)─свет─>( )─закрой─>( )─дверь─>( )
#1 свет     @0.4  ●═выключи═>(*)═свет═>(*)─закрой─>( )─дверь─>( )   ✓ «свет: выключить»
#2 закрой   @5.4  ●─выключи─>( )─свет─>( )─закрой─>( )─дверь─>( )   истекли сроки 3.0 и 3.4: совпадения сняты
                  ●═закрой═>(*)─дверь─>( )                          + новое из начала
#3 дверь    @5.8  ●═закрой═>(*)═дверь═>( )                          ✓ «дверь: закрыть»
```

В последней фразе [examples/stream.txt](examples/stream.txt) от «свет» до
«закрой» ровно 3 с, поэтому там срабатывает ещё и «ухожу из дома». «Потом»
между ними срок не продлевает.

**«выключи», `<дверь>`, «свет», `<громкий звук>`: задержка считается между шагами своего сценария**

| Событие | Что происходит |
|---|---|
| #0 выключи @0.0 | совпадение «выключи» ждёт «свет» до 3.0 |
| #1 `<дверь>` @0.5 | начинаются два совпадения: «взлом» ждёт `<громкий звук>` до 10.5, «кто-то вошёл» ждёт `<шаги>` до 5.5 |
| #2 свет @4.0 | 4.0 > 3.0: совпадение «выключи» снято, «свет: выключить» не срабатывает |
| #3 `<громкий звук>` @7.0 | 7.0 ≤ 10.5: ✓ «взлом». Срок «кто-то вошёл» истёк в 5.5, совпадение снято |

Между `<дверь>` и «свет» пауза 3.5 с, но «взлому» она не мешает: срок
отсчитывается от его собственного шага `<дверь>`, а задержка у него 10 с.

**«выключи, пожалуйста, пожалуйста, свет»: посторонние токены срок не продлевают**

```
#0 выключи     @0.0  ●═выключи═>(*)─свет─>( )   ждёт до 3.0
#1 пожалуйста  @2.5  ●═выключи═>(*)─свет─>( )   ребра «пожалуйста» нет: ждёт до 3.0
#2 пожалуйста  @5.0  ●─выключи─>( )─свет─>( )   5.0 > 3.0: совпадение снято
#3 свет        @7.5  ●─выключи─>( )─свет─>( )   «свет: выключить» не срабатывает
```

Между соседними токенами по 2.5 с, но срок отсчитывается от последнего шага
совпадения — от «выключи».

**`<дверь>`, через 4 с `<шаги>`: у шага своя задержка**

| Событие | Что происходит |
|---|---|
| #0 `<дверь>` @0.0 | «кто-то вошёл» ждёт `<шаги>` до 5.0, «взлом» ждёт `<громкий звук>` до 10.0 |
| #1 `<шаги>` @4.0 | 4.0 ≤ 5.0: ✓ «кто-то вошёл» |

Со стандартной задержкой 3 с «кто-то вошёл» здесь не сработал бы. Три последних
примера лежат в [examples/gaps.txt](examples/gaps.txt), там группы сдвинуты по
времени.

**«<дверь> <громкий звук>»: сигналы — такие же токены, у сценария несколько шаблонов**

```
#0 <дверь>         {<дверь>}                   «взлом» ждёт <громкий звук> до 10.0
#1 <громкий звук>  {<дверь>, <громкий звук>}   ✓ «взлом»
```

Показан только набор «взлома»: `<дверь>` начинает ещё и «кто-то вошёл» в
дереве. Два других шаблона «взлома» — одиночные сигналы:
`<громкое открывание двери>` или `<стекло разбилось>` сразу дают «взлом».

**«<дверь> <шаги> <громкий звук>»: лишний сигнал не мешает**

| Событие | Что происходит |
|---|---|
| #0 `<дверь>` | начинаются «взлом» (набор `{<дверь>}`) и «кто-то вошёл» (вершина `<дверь>` в дереве) |
| #1 `<шаги>` | ✓ «кто-то вошёл»; «взлому» `<шаги>` не нужны, его совпадение ждёт дальше |
| #2 `<громкий звук>` | ✓ «взлом» |

Когда вершина у сценариев общая, тот же результат даёт копия: так
«включи чайник и свет в спальне» из [examples/repeats.txt](examples/repeats.txt)
даёт оба сценария.

**«<стекло разбилось>» трижды подряд: у «взлома» cooldown 60 с, тревога одна**

```
#0 <стекло разбилось>  @0.0  {<стекло разбилось>}   ✓ «взлом»
#1 <стекло разбилось>  @0.8  {<стекло разбилось>}   0.8 с после тревоги < 60 с: молчим
#2 <стекло разбилось>  @1.5  {<стекло разбилось>}   1.5 с < 60 с: молчим
```

Все группы сигналов лежат в [examples/alarm.txt](examples/alarm.txt).

**«<громкий звук> <дверь>»: у «взлома» порядок любой**

```
#0 <громкий звук>  @0.0  {<громкий звук>}           ждёт <дверь> до 10.0
#1 <дверь>         @2.0  {<громкий звук>, <дверь>}   ✓ «взлом» (0.85)
                         {<дверь>}                   + новый набор: ждёт <громкий звук> до 12.0
```

`<дверь>` и продолжает старый набор, и начинает новый: новый пригодится, если
придёт ещё один звук. Задержка 10 с отсчитывается от последнего сигнала набора,
поэтому дверь через 12 с после звука «взлома» уже не даёт.

**«<дверь> <громкий звук> <дверь>»: одна тревога**

| Событие | Что происходит |
|---|---|
| #0 `<дверь>` @0.0 | набор `{<дверь>}` ждёт звук до 10.0 |
| #1 `<громкий звук>` @1.0 | ✓ «взлом» по #0 #1. Новый набор `{<громкий звук>}` ждёт дверь до 11.0 |
| #2 `<дверь>` @2.0 | дверь дополняет набор `{<громкий звук>}`: #1 #2. Токен #1 уже вошёл в тревогу, повтора нет |

Без общего токена вторую тревогу заглушил бы cooldown. Если шаги придут раньше
двери, «взлом» сработает, а «кто-то вошёл» нет: у него порядок по умолчанию,
`sequence`. Эти примеры лежат в [examples/order.txt](examples/order.txt).

**«выключи свет свет», первый «свет» неуверенный: токен ниже порога для ребра не существует**

| Событие | Что происходит |
|---|---|
| #0 выключи 0.95 @0.0 | совпадение «выключи» ждёт «свет» до 3.0 |
| #1 свет 0.40 @0.4 | 0.40 < 0.5: для ребра «свет» токена нет, совпадение ждёт дальше |
| #2 свет 0.90 @0.9 | ✓ «свет: выключить» (0.92) из #0 #2 |

Если неуверенным будет «выключи», совпадение не начнётся вовсе, и «свет» после
него ничего не даст.

**`<дверь>`, `<громкий звук>` 0.40: у «взлома» свой порог 0.3**

| Событие | Что происходит |
|---|---|
| #0 `<дверь>` 0.95 @0.0 | «взлом» ждёт `<громкий звук>` до 10.0 |
| #1 `<громкий звук>` 0.40 @1.0 | 0.40 ≥ 0.3: ✓ «взлом» (0.62) |

Со стандартным порогом 0.5 звук бы не засчитался. Так же засчитываются тихие
`<шаги>` 0.40 в «кто-то вошёл»: у этого шага свой порог 0.3.

**`<дверь>` 0.40, `<шаги>`, `<громкий звук>`: у сценариев разные пороги для одного токена**

| Событие | Что происходит |
|---|---|
| #0 `<дверь>` 0.40 @0.0 | 0.40 ≥ 0.3: «взлом» ждёт `<громкий звук>` до 10.0. 0.40 < 0.5: «кто-то вошёл» не начинается |
| #1 `<шаги>` 0.80 @1.0 | ждущего `<шаги>` совпадения нет, «кто-то вошёл» не срабатывает |
| #2 `<громкий звук>` 0.95 @2.0 | ✓ «взлом» (0.62) |

Все примеры с порогами токена лежат в [examples/scores.txt](examples/scores.txt).

**Две `<дверь>`: уверенное совпадение и свежее стоят рядом**

| Событие | Что происходит |
|---|---|
| #0 `<дверь>` 0.90 @0.0 | совпадение A ждёт `<громкий звук>` до 10.0 |
| #1 `<дверь>` 0.40 @8.0 | совпадение B ждёт до 18.0. A увереннее, B проживёт дольше: ни одно не вытесняет другое, в наборе `{<дверь>}` стоят оба |
| #2 `<громкий звук>` 0.80 @9.0 | A даёт √(0.90·0.80) = 0.85, B — √(0.40·0.80) = 0.57 < 0.6. ✓ «взлом» (0.85) по A |

Если бы в вершине держалось одно свежее совпадение, «взлом» здесь не сработал
бы. Если `<громкий звук>` придёт в 11.0, срок A уже истёк, а B даёт 0.57:
«взлом» не срабатывает.

**`<дверь>` 0.95, `<громкий звук>` 0.35: общая уверенность — среднее геометрическое**

| Событие | Что происходит |
|---|---|
| #0 `<дверь>` 0.95 @0.0 | «взлом» ждёт `<громкий звук>` до 10.0 |
| #1 `<громкий звук>` 0.35 @1.0 | 0.35 ≥ 0.3, шаг пройден, но √(0.95·0.35) = 0.58 < 0.6: «взлом» не срабатывает |

Среднее арифметическое дало бы 0.65: уверенная дверь перекрыла бы слабый звук,
хотя взлом отличает именно звук. Произведение наказывало бы длину: шесть
токенов по 0.9 дают 0.53.

**`<дверь>` 0.31: ранний отсев**

| Событие | Что происходит |
|---|---|
| #0 `<дверь>` 0.31 @0.0 | 0.31 ≥ 0.3, но даже при `<громкий звук>` 1.0 выйдет √0.31 = 0.56 < 0.6: совпадение снимается сразу |
| #1 `<громкий звук>` 1.00 @1.0 | ждущей двери нет, «взлом» не срабатывает. Звук начинает свой набор и ждёт `<дверь>` до 11.0 |

**«выключи свет, закрой дверь» неуверенно: у «ухожу из дома» свой порог 0.8**

| Событие | Что происходит |
|---|---|
| #0 выключи 0.70 @0.0 | совпадение «выключи» ждёт «свет» до 3.0 |
| #1 свет 0.75 @0.4 | ✓ «свет: выключить» (0.72). Совпадение ждёт «закрой» до 3.4 |
| #2 закрой 0.70 @1.9 | даже при «дверь» 1.0 «ухожу из дома» дал бы (0.70·0.75·0.70)^(1/4) = 0.78 < 0.8, поэтому продолжение «выключи свет закрой» отсеяно. Новое «закрой» ждёт «дверь» до 4.9 |
| #3 дверь 0.80 @2.3 | ✓ «дверь: закрыть» (0.75) |

Все примеры общей уверенности лежат в
[examples/confidence.txt](examples/confidence.txt).

## Форматы

Правила лежат в [examples/smart_home.json](examples/smart_home.json):

```json
{
  "max_gap": 3.0,
  "min_score": 0.5,
  "min_confidence": 0.6,
  "vocabulary": ["выключи", "свет", "закрой", "дверь", "<дверь>", "<шаги>",
                 "<громкий звук>", "<стекло разбилось>"],
  "scenarios": [
    {"name": "свет: выключить", "patterns": [["выключи", "свет"]]},
    {"name": "ухожу из дома", "min_confidence": 0.8,
     "patterns": [["выключи", "свет", "закрой", "дверь"]]},
    {"name": "взлом", "order": "any", "max_gap": 10.0, "min_score": 0.3, "cooldown": 60.0,
     "patterns": [["<дверь>", "<громкий звук>"], ["<стекло разбилось>"]]},
    {"name": "кто-то вошёл",
     "patterns": [["<дверь>", {"token": "<шаги>", "max_gap": 5.0, "min_score": 0.3}]]}
  ]
}
```

`max_gap` в корне обязателен: это стандартная задержка между шагами в секундах.
`min_score` и `min_confidence` в корне тоже обязательны: это стандартные пороги
уверенности токена и общей уверенности сценария, числа от 0 до 1. `patterns` —
непустой список шаблонов-альтернатив, шаблон — непустой список шагов. Шаблон
записывается списком, а не строкой через пробел, потому что в токене бывают
пробелы.

Шаг — строка с токеном из словаря или объект
`{"token": ..., "max_gap": ..., "min_score": ...}`. Задержка шага — наибольшее
время от предыдущего шага шаблона до этого, порог шага — наименьшая уверенность
токена, которую шаг принимает. Обе настройки берутся у самого шага; если их там
нет — у сценария (`max_gap` и `min_score` сценария); если нет и там — из корня.
У первого шага задержки нет: новое совпадение её не проверяет, поэтому `max_gap`
у него вызывает ошибку. Порог у первого шага есть. Задержка — положительное
конечное число, порог — число от 0 до 1.

`min_confidence` сценария — его порог общей уверенности; если его нет, берётся
порог из корня. У шага этого ключа нет. Общая уверенность не бывает ниже
наименьшего порога шагов, поэтому `min_confidence` имеет смысл, только если он
выше `min_score`.

`order` — необязательный ключ сценария: `"sequence"` (по умолчанию) — шаги идут
по порядку шаблона, `"any"` — в любом порядке. У шагов `any` нет своей
задержки: она одна на сценарий и считается между соседними по времени шагами,
поэтому `max_gap` у шага `any` вызывает ошибку. Порог у шага `any` свой бывает.
Одинаковые шаги в шаблоне `any` ждут разных событий.

Одинаковые шаблоны в одном сценарии (те же токены с теми же задержками и
порогами; у `any` — в любом порядке), одна последовательность шагов у двух
сценариев и один набор `any` у двух сценариев вызывают ошибку.
Неизвестный ключ в корне, у сценария или у шага тоже вызывает ошибку: опечатка
не теряется молча.

`cooldown` — необязательный ключ сценария: неотрицательное число секунд, по
умолчанию 0. Ставит его автор правил тем сценариям, чей повтор нужно глушить;
токены движок при этом обрабатывает одинаково. В примере cooldown есть только у
«взлома»: у команды он заглушил бы настоящий повтор.

Звуковые сигналы записываются в угловых скобках: `<дверь>`, `<громкий звук>`.
Это только соглашение об именах: движок скобки не разбирает и сравнивает токены
как строки целиком. Поэтому сказанное «дверь» и звук `<дверь>` — разные токены,
и громко сказанное «закрой дверь» не станет взломом.

Потоки лежат в [examples/](examples/) (`stream.txt`, `pause.txt`, `alarm.txt`,
`repeats.txt`, `gaps.txt`, `scores.txt`, `confidence.txt`, `order.txt`): одна строка на
событие, в формате `токен уверенность время`. Токеном считается всё до двух
последних чисел, поэтому в нём бывают пробелы: `<громкий звук> 0.62 12.4`.
Пустые строки и строки, начинающиеся с `#`, пропускаются. Уверенность — число
от 0 до 1, движок сравнивает её с порогом шага и считает по ней общую
уверенность.

Время задаётся в секундах: это момент, когда токен сказан. Метку ставит
детектор, а не движок, потому что порция токенов приходит к движку разом.
Начало отсчёта одно на весь поток: в работе это Unix time, в примерах — начало
записи. Задержкам нужны только разности времён.

`cli run` печатает строку на срабатывание: сценарий, его общую уверенность и шаги.
У каждого шага в скобках — токен, его уверенность и время:

```
✓ взлом, уверенность 0.85 — [<дверь> 0.90, 0.0 с] [<громкий звук> 0.80, 9.0 с]
незавершённых совпадений в конце потока: 3
```

Последняя строка — сколько частичных совпадений ещё ждут продолжения.

## Устройство кода

Код разделён на слои, зависимости идут только вниз:

```
main.py — выбирает интерфейс: rule-engine cli … | rule-engine web …
   ├─> interfaces/cli ─┐   argparse, текст
   └─> interfaces/web ─┤   контроллер, HTML и SVG; server.py — FastAPI
                       ▼
                application/   RuleEngineService, view-модели, формат потока
                       ▼
                   domain/     правила, граф, проход потока
```

CLI и веб взаимозаменяемы: оба работают только через `RuleEngineService` и не
видят объектов домена, а друг о друге не знают. Фреймворк знает только
`server.py`.

- [main.py](src/rule_engine/main.py): точка сборки, выбор интерфейса;
- [domain/rules.py](src/rule_engine/domain/rules.py): словарь и сценарии, загрузка JSON, проверки;
- [domain/graph.py](src/rule_engine/domain/graph.py): построение графа;
- [domain/unordered.py](src/rule_engine/domain/unordered.py): шаблоны сценариев с `"order": "any"`;
- [domain/engine.py](src/rule_engine/domain/engine.py): проход потока по графу и по наборам `any`, снимок совпадений, отказы;
- [application/service.py](src/rule_engine/application/service.py): сценарии использования — граф и прогон;
- [application/views.py](src/rule_engine/application/views.py): view-модели — граф, кадры, срабатывания;
- [application/stream.py](src/rule_engine/application/stream.py): формат потока;
- [interfaces/base.py](src/rule_engine/interfaces/base.py): контракт `Interface`;
- [interfaces/cli/](src/rule_engine/interfaces/cli): командная строка и печать графа;
- [interfaces/web/](src/rule_engine/interfaces/web): контроллер, презентер, раскладка SVG, шаблоны, статика;
- [interfaces/web/server.py](src/rule_engine/interfaces/web/server.py): маршруты FastAPI.

## Все примеры

```bash
uv run rule-engine cli graph examples/smart_home.json                        # показать граф
uv run rule-engine cli run examples/smart_home.json examples/stream.txt      # прогнать поток
uv run rule-engine cli run examples/smart_home.json examples/pause.txt       # задержка больше 3 с
uv run rule-engine cli run examples/smart_home.json examples/alarm.txt       # звуковые сигналы
uv run rule-engine cli run examples/smart_home.json examples/repeats.txt     # копии и повторы
uv run rule-engine cli run examples/smart_home.json examples/gaps.txt        # задержки между шагами
uv run rule-engine cli run examples/smart_home.json examples/scores.txt      # пороги уверенности токена
uv run rule-engine cli run examples/smart_home.json examples/confidence.txt  # общая уверенность
uv run rule-engine cli run examples/smart_home.json examples/order.txt       # любой порядок
uv run rule-engine web examples                                              # всё то же в браузере
uv run pytest
```
